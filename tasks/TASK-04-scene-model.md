## Семантика отношений (вид сбоку, col →вправо, row →вниз)

Обозначим субъект S, ориентир R (с учётом `w`/`h`: сущность занимает диапазон ячеек; «та же колонка/строка» — пересечение диапазонов).

| relation | истинно, когда |
|---|---|
| `left` (왼쪽) | S левее R: `S.col + S.w <= R.col`, пересечение по строкам |
| `right` (오른쪽) | S правее R, пересечение по строкам |
| `beside` (옆) | S вплотную слева или справа от R (соседние ячейки), та же строка |
| `above` (위) | S выше R (row меньше), пересечение по колонкам |
| `below` (아래) | S ниже R, пересечение по колонкам |
| `front` (앞) | сцена `street`: S на «переднем» ряду (row R.row+R.h) в колонках R; сцены `classroom`/`room`: S вплотную перед R по колонке (row на 1 больше), т.е. визуально «перед» |
| `behind` (뒤) | зеркально front: S в ряду за R (row меньше R.row) в тех же колонках — только для `street` (за зданием) |
| `inside` (안) | `S.containerId === R.id` |
| `outside` (밖) | у S нет `containerId === R.id`, и R — building/room, и S «рядом» с R (near) |
| `between` (사이) | R1, R2: одна строка с S, `S.col` строго между ними |
| `near` (근처) | чебышёвское расстояние между прямоугольниками S и R ≤ 1, и не inside |

Примечания:
- `beside` истинно ⇒ `near` тоже истинно; `left`/`right` могут быть истинны одновременно с `beside`. Это нормально: `getTrueRelations` возвращает ВСЕ истинные факты.
- В `getTrueRelations` не включать пары с `decor`-сущностями и самого себя; `between` перебирать по парам сущностей одной строки.
- В `building-cut` этажи — строки; «위/아래» между помещениями работают через пересечение колонок; `inside` — помещение внутри здания, человек внутри помещения (`containerId`).

## `resolveTargetCell(scene, subjectId, fact)`

Вернуть ячейку (и `containerId` для inside), встав в которую субъект сделает `fact` истинным:
- перебрать кандидатные ячейки согласно таблице выше (например, для `beside` — ячейка слева и справа от R; для `between` — ячейки строго между R1 и R2 на их строке; для `inside` — ячейка внутри R + `containerId: R.id`);
- ячейка должна быть в границах сетки и не занята немувабельной сущностью (пересечение прямоугольников);
- если кандидатов несколько — брать ближайшую к текущей позиции субъекта (по чебышёвскому расстоянию);
- нет кандидатов → `null`.

После «перемещения» вызывающий код меняет только `col`/`row`/`containerId` субъекта — функция сама сцену не мутирует.

## Тесты — `src/lib/scene/relations.test.ts`

Собрать мини-сцену `street` (3 здания в ряд, дерево, человек) и `building-cut` (2 этажа × 2 помещения, человек в одном) и проверить:
- `getTrueRelations` для человека между двумя зданиями содержит `between` и `near`;
- `holds` для above/below в разрезе здания;
- `inside`/`outside` через `containerId`;
- `resolveTargetCell` для `beside`, `between`, `inside`: возвращает ожидаемую ячейку; для невозможного факта → `null`;
- после применения ячейки из `resolveTargetCell` соответствующий `holds` становится `true` (roundtrip-инвариант — прогнать по всем relation минимум по одному разу).
