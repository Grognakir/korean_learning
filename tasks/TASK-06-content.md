# TASK-06 — Контент: сцены, задания, словарь ритм-игры

Контекст: `tasks/ARCHITECTURE.md`. Зависимости: TASK-02, TASK-04 (типы), TASK-05 (`SpriteId`).

## Цель

`src/content/topics/location.ts` — все данные темы: 4 сцены, ≥12 заданий, словарь для ритм-игры. Типы `LocationTask`, `VocabWord` — из ARCHITECTURE.md (объявить здесь же и экспортировать).

## Сцены (id, kind, наполнение)

1. **`street`** (улица, ~7×3): ряд зданий (은행, 약국, 서점, 카페, 편의점), дерево, персонаж 민수 (`movable`). Ряды: 0 — «за зданиями», 1 — здания, 2 — тротуар/дорога перед ними. Дорогу отдельной сущностью НЕ добавлять — её рисует фон сцены (SceneCanvas, kind "street"); иначе она заблокирует ячейки, по которым ходит персонаж. Между зданиями, используемыми в beside/between-целях, оставлять свободные ячейки.
2. **`classroom`** (класс, ~6×3): 칠판 (стена, row 0), 문, 창문, парты 책상 ×2, 의자, 가방, 책, 컴퓨터, 시계 (на стене), персонажи 유나 (`movable`) и 지훈.
3. **`building-cut`** (разрез здания, ~4×3): 3 этажа; помещения: 3층 사무실, 2층 도서관 и 화장실, 1층 식당 и 카페-холл (kind `room`, `containerId` — здание не нужен, здание рисует фон); персонаж 수진 (`movable`, `containerId` = помещение, где стоит).
4. **`room`** (комната, ~6×3): 침대, 소파, 탁자, 책상, 컴퓨터, 창문, 문, 시계; персонажи 민수 (`movable`) и 유나.

Требования: id сущностей = lexemeId из `lexicon.ts` (уникальность в сцене: если предмет один — просто lexemeId, дубликаты — `desk-1`, `desk-2`, но тогда в заданиях их не использовать как ориентир, либо использовать только один); все использованные слова обязаны быть в lexicon.

## Задания (`export const tasks: LocationTask[]`)

Минимум 12, покрыть все 4 сцены и все три типа:

- **describe** ×4 (по одному на сцену): напр. `{ type: "describe", sceneId: "street", subjectId: "pharmacy", promptRu: "Напиши по-корейски, где находится аптека (약국)" }`. Проверка засчитает любое истинное отношение.
- **command** ×5: цели с разными relation (front, beside, between, inside, above/below), напр. «Сделай так, чтобы Минсу оказался между банком и книжным. Напиши это предложение по-корейски».
- **fix** ×3: `wrongSentence` — грамматически корректное, но фактически неверное или с неверной частицей предложение; `goal` — что должно получиться. Примеры: `가방이 책상 아래에 있어요` при цели above; `민수가 카페 옆에 있어요` при цели «рядом с 은행»; одно предложение с ошибкой частицы (`은행가 …`).

Для каждого command/fix: убедиться (хотя бы вручную по семантике TASK-04), что `resolveTargetCell` для goal в этой сцене достижим (есть свободная ячейка).

`promptRu` — короткая формулировка по-русски; корейские слова в ней дублировать хангылем в скобках.

## Словарь ритм-игры (`export const vocab: VocabWord[]`)

Все позиционные слова (앞, 뒤, 옆, 위, 아래, 밑, 안, 밖, 사이, 근처, 왼쪽, 오른쪽) + 12–15 существительных темы из lexicon. Перевод — краткий (1–2 слова).

## Тест — `src/content/topics/location.test.ts`

- каждый `sceneId`/`subjectId`/`refIds` в заданиях существует в соответствующей сцене;
- для каждого command/fix `resolveTargetCell(scene, subjectId, goal) !== null`;
- для каждого fix: `parseLocationSentence(wrongSentence, ids сцены)` либо парсится (факт ≠ goal), либо даёт ошибку частицы — т.е. предложение «чинится» в рамках грамматики парсера;
- все `ko` из vocab и сцен есть в lexicon (кроме имён этажей типа 3층 — их в vocab не включать, 층 включить отдельным словом).
